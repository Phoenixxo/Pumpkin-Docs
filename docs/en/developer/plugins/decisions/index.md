# Design decisions

These records explain choices in the [plugin subsystem design](../design). They are draft proposals for review, not a statement that the maintainers have adopted the architecture.

| Record | Review state | Subject |
| --- | --- | --- |
| [0001](./0001-async-execution) | Proposed | A v0.2-only target after migration |
| [0002](./0002-invocation-context) | Proposed | Explicit invocation identity and authority |
| [0003](./0003-event-decisions) | Proposed | Event facts, decision state, and commit |
| [0004](./0004-component-contracts) | Proposed | Typed component dependencies and extension points |
| [0005](./0005-contract-versioning) | Proposed | Contract versions independent of implementation releases |

Each record states the context, the decision, the alternatives considered, and the consequences. Review state is Proposed, Accepted, Rejected, or Superseded. A decision that changes gets a new record that supersedes the old one, linked in both directions.
